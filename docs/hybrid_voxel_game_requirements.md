# 传统3D地形 + 上层体素世界 游戏需求规划书

**文档版本**：v0.1  
**文档类型**：概念需求与MVP规划  
**适用对象**：后续结合 AI Agent 进行最小可行性产品（MVP）实现  
**更新日期**：2026-11-06

---

## 1. 项目概述

### 1.1 核心概念

本项目旨在实现一种**混合世界架构**：主体世界采用传统3D场景（类似《流放者柯南》的固定地形与精细模型），在特定区域（如大峡谷、泥土地、沙地、可挖掘矿区等）动态叠加一层**体素世界**。玩家可以在体素层内自由挖掘与放置方块，直到挖到底部不可挖掘的传统3D地形为止。

这种设计融合了两种玩法：
- 传统3D场景的精细视觉、叙事氛围与固定关卡结构
- 体素系统的自由建造、地形改造与沙盒乐趣

体素层并非覆盖整个世界，而是按区域、剧情或玩法需求局部启用，以控制性能与美术成本。

### 1.2 设计目标

- 在传统3D地形之上实现可编辑的体素层
- 体素层与底层传统地形之间实现相对平滑的视觉与碰撞衔接
- 支持玩家在体素层内挖掘、放置、建造基地
- 为后续MVP实现提供清晰、可落地的需求边界

---

## 2. 世界结构

### 2.1 分层架构

| 层级 | 类型 | 特性 | 是否可编辑 |
|------|------|------|-----------|
| 底层 | 传统3D地形（高度图 + 网格 + 碰撞体） | 固定、精细模型、非网格化 | 不可挖掘 |
| 上层 | 体素层（离散方块网格） | 可动态生成、分块管理 | 可挖掘、可放置 |
| 过渡区 | 混合区域 | 高度对齐、边缘平滑 | 部分可编辑 |

### 2.2 体素层启用规则

- 按**区域触发**：进入特定体积（Volume）、生物群系或剧情区域时启用体素系统。
- 按**地形材质标记**：例如泥土、沙地、可挖掘岩石区域。
- 体素层底部高度应对齐到底层传统地形的表面（或略低于），挖到后停止挖掘。
- 非启用区域仅显示传统3D场景，不加载体素数据。

## 3. 核心玩法需求

### 3.1 挖掘

- 玩家可在体素层内向下、向四周挖掘。
- 挖掉方块后暴露下层内容，最终挖到底部传统3D地形时停止。
- 不同材质的方块可有不同硬度（MVP阶段可先统一）。
- 挖掘操作应实时更新体素数据与渲染网格。

### 3.2 放置

- 玩家可在体素层任意有效位置放置方块（包括向上堆叠）。
- 放置后应支持基础碰撞。
- MVP阶段可先支持少数几种方块类型（如泥土、石头、木板）。

### 3.3 基地建设

- 玩家可在体素层内自由搭建结构。
- 后续可支持在体素结构上放置传统3D模型（家具、装饰等），实现混合风格。

### 3.4 平滑衔接（关键需求）

系统需通过算法使放置的多个方块之间、以及体素层与传统地形之间实现相对平缓的衔接：

- **高度对齐**：体素层最底层方块高度根据下方传统地形高度图动态调整。
- **边缘混合**：体素区域与非体素区域边界使用渐变或过渡方块/网格。
- **表面处理**：对体素表面进行局部平滑（可参考简化版 Marching Cubes、Surface Nets 或高度插值），减少纯方块感。
- **碰撞统一**：底层传统地形与上层体素方块共享或融合碰撞，避免穿模、卡人。

## 4. 技术实现要点（面向MVP）

### 4.1 数据表示

- **底层地形**：使用高度图或预烘焙网格 + 碰撞体。
- **体素层**：使用分块（Chunk）存储。每个 Chunk 为固定大小的三维数组（推荐 16×16×16 或 32×32×32）。
- 仅在启用区域生成/加载体素 Chunk。
- 体素数据需支持运行时修改（挖掘/放置）。

### 4.2 网格生成

- 体素 Chunk 修改后实时或异步重建表面网格。
- 推荐算法：
  - 简单实现：贪婪网格合并（Greedy Meshing）或基础立方体渲染
  - 更平滑：简化 Surface Nets 或 Marching Cubes
- 底层传统地形与体素网格在边界处进行混合或遮罩处理。

### 4.3 碰撞

- 体素网格生成后同步更新碰撞体（Mesh Collider 或简化碰撞）。
- 底层地形碰撞始终存在。
- 边界处做碰撞体融合或优先级处理。

### 4.4 性能优化

- 分块加载与卸载（仅加载玩家附近 Chunk）。
- 修改时仅重建受影响的 Chunk 及其邻居。
- 使用 LOD 或距离剔除。
- 限制同时可编辑的体素区域范围（MVP 建议控制在较小测试场景）。

### 4.5 存档

- 需同时保存：
  - 传统地形状态（通常为静态）
  - 体素修改数据（仅保存与默认状态不同的 Chunk）
- MVP 阶段可先使用简单序列化（JSON 或二进制）。

## 5. MVP 范围建议

### 5.1 必须实现（核心验证）

- [ ] 一个小型测试场景：底层为固定传统3D地形，上方局部区域启用体素层
- [ ] 体素分块存储与基础渲染
- [ ] 挖掘与放置操作（至少支持2-3种方块）
- [ ] 挖到底部传统地形时停止挖掘
- [ ] 基础高度对齐（体素底部贴合地形表面）
- [ ] 简单碰撞（玩家可站立、挖掘、放置）
- [ ] 基础存档与读取（体素修改）

### 5.2 建议实现（提升体验）

- [ ] 边缘平滑或过渡处理（减少明显断层）
- [ ] 多种方块材质与基础纹理
- [ ] 简单的 Chunk 加载范围控制
- [ ] 调试可视化（显示体素边界、Chunk 范围）

### 5.3 暂不实现（后续迭代）

- 复杂物理（流体、结构坍塌）
- 高级平滑算法（完整 Marching Cubes / Dual Contouring）
- 大型开放世界与远距离流式加载
- 多人同步
- 复杂AI寻路与NPC在混合地形上的导航
- 丰富的建造UI与道具系统

## 6. 关键算法与技术方向

### 6.1 体素与传统地形衔接

1. 采样底层高度图，确定每个体素列的起始高度。
2. 在边界区域生成过渡网格或使用 shader 混合。
3. 碰撞体在交界处做 union 或优先级覆盖。

### 6.2 表面生成优先级（MVP）

1. **第一阶段**：纯立方体渲染 + 贪婪合并（最快验证）
2. **第二阶段**：局部高度插值或简单表面平滑
3. **第三阶段**：引入 Surface Nets 或类似算法进一步降低方块感

### 6.3 区域控制

- 使用 Volume 或地形材质标签标记可体素化区域。
- 运行时仅在标记区域内生成体素数据。

## 7. 风险与注意事项

| 风险 | 说明 | 缓解建议 |
|------|------|---------|
| 视觉断层 | 体素与传统地形衔接不自然 | MVP先做高度对齐，后续再做边缘混合 |
| 性能 | 大范围体素重建开销大 | 严格控制可编辑区域大小，使用分块异步更新 |
| 碰撞问题 | 边界处穿模或卡住 | 统一碰撞生成逻辑，充分测试边界情况 |
| 存档体积 | 体素修改数据可能较大 | 仅保存差异数据，使用压缩 |
| AI实现难度 | 网格生成与混合算法较复杂 | MVP优先验证核心循环，算法可逐步优化 |

---

## 8. 后续扩展方向

- 体素层上放置传统3D模型（家具、建筑模块、NPC）
- 更高级的表面重建与材质混合
- 结构稳定性与物理破坏
- 更大范围的体素区域与流式加载
- 剧情驱动的区域动态开启/关闭
- 与传统3D场景的更深度融合（如体素洞穴连接到固定关卡）

---

## 9. 总结

本需求规划书定义了一种**“传统3D世界 + 局部体素叠加”**的混合架构。核心价值在于保留传统场景的视觉与叙事优势，同时在特定区域提供类似《我的世界》的自由挖掘与建造体验。

MVP的重点应放在：
1. 体素层的分块存储与基础渲染
2. 挖掘/放置的核心循环
3. 与底层传统地形的基本高度对齐与碰撞

后续可通过 AI Agent 逐步实现上述功能，并在验证核心玩法后迭代平滑算法与体验优化。
